# 07 通知系统（站内通知）

## 模块简介

通知系统是 B 站式视频社区的"互动反馈中枢"：当别人点赞、收藏、投币、评论、回复或关注你时，系统会给被影响的一方写入一条站内通知，用户可以在"消息通知"页面查看，导航栏的铃铛上会显示未读红点数。

本项目通知的**产生时机**不在通知模块自身，而是由各个互动行为（点赞/收藏/投币/评论/回复/关注）在各自的服务层触发 `NotificationService.notify()` 完成落库；通知模块只负责**产生**（提供统一的写入入口）与**消费**（分页查询、已读管理、未读数统计）。数据量级为练习规模，直接单表查询 + 联查昵称/标题即可满足，无需引入消息队列。

## 功能清单

| 功能 | 说明 | 涉及接口/组件 |
| --- | --- | --- |
| 通知产生（点赞/收藏/投币） | 视频作者收到一条通知 | `VideoServiceImpl.notifyOwner()` + `NotificationType.LIKE/FAVORITE/COIN` |
| 通知产生（评论/回复） | 一级评论通知视频作者，楼中楼回复通知被回复者 | `VideoServiceImpl.addComment()` |
| 通知产生（关注） | 关注成功时通知被关注者 | `FollowServiceImpl.toggleFollow()` |
| 通知列表分页查询 | 按时间倒序，一页 15 条 | `GET /api/notification/list` |
| 未读通知数 | 导航栏铃铛红点数字 | `GET /api/notification/unread-count` |
| 单条标记已读 | 点击通知后置为已读（校验归属） | `POST /api/notification/read/{id}` |
| 全部标记已读 | 一键清除所有未读 | `POST /api/notification/read-all` |
| 导航栏红点轮询 | 每 30 秒刷新通知/私信红点 | `frontend/src/components/NavBar.vue` |

## 涉及数据表

### user_notification（站内通知表）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键，自增 |
| user_id | BIGINT | 接收者（被通知的人） |
| actor_id | BIGINT | 触发者（谁点的赞/评论的） |
| type | TINYINT | 通知类型：1点赞 2收藏 3投币 4评论 5回复 6关注 |
| video_id | BIGINT | 关联视频 ID（关注通知为空） |
| content | VARCHAR(200) | 通知摘要文本（服务端拼好） |
| is_read | TINYINT | 0未读 1已读，默认 0 |
| create_time | DATETIME | 通知时间，默认当前时间 |

表上建有索引 `idx_user_read (user_id, is_read)`，支撑两类高频查询：某用户的全部通知（按 user_id 过滤）、某用户的未读数（按 user_id + is_read 过滤）。

## 后端实现

### 1. 通知类型常量 `constant/NotificationType.java`

通知类型用 int 常量集中定义，与数据库 `type` 字段一一对应，避免各处散写魔法数字：

public class NotificationType {

    /** 回复了你的评论 */
    public static final int REPLY = 5;
    /** 关注了你 */
    public static final int FOLLOW = 6;

    private NotificationType() {
    }
}

### 3. 服务接口 `service/NotificationService.java`

接口定义两个职责：**查询/已读**（通知中心用）与**产生**（互动触发点用）：

```java
public interface NotificationService {
    /** 分页查询我的通知（按通知时间倒序） */

    /**
     * 创建一条通知（互动行为触发时调用）
     * @param userId  接收者（被通知的人）
     * @param actorId 触发者（谁点的赞）
     * @param type    通知类型（见 constant.NotificationType）
     * @param videoId 关联视频 ID（关注通知传 null）
     * @param extra   附加文本（评论内容/回复内容，其他类型传 null）
     */
    void notify(Long userId, Long actorId, int type, Long videoId, String extra);
}
```

### 4. 通知产生 `NotificationServiceImpl.notify()`

所有互动行为最终都汇聚到这一个入口。核心逻辑：

- **自己触发自己的行为不通知自己**（给自己点赞、评论自己的视频都不打扰）；
- 联查触发者昵称与视频标题，按类型拼接通知文案后落库。

```java
@Override
public void notify(Long userId, Long actorId, int type, Long videoId, String extra) {
    // 自己触发自己的行为不通知自己（给自己点赞、评论自己的视频都不打扰）
    if (userId == null || userId.equals(actorId)) {
        return;
    }
    User actor = userMapper.selectById(actorId);
    String nickname = actor == null ? "匿名用户" : actor.getNickname();
    Video video = videoId == null ? null : videoMapper.selectById(videoId);
    String title = video == null ? "" : video.getTitle();

    UserNotification n = new UserNotification();
    n.setUserId(userId);
    n.setActorId(actorId);
    n.setType(type);
    n.setVideoId(videoId);
    n.setContent(buildContent(nickname, type, title, extra));
    n.setIsRead(0);
    notificationMapper.insert(n);
}
```

文案拼接用 Java 17 的 `switch` 表达式按类型生成，如"用户0003 赞了你的视频《xxx》"；评论类通知会附上评论内容片段，超过 50 字截断，避免长评论刷屏：

```java
private String buildContent(String nickname, int type, String title, String extra) {
    String suffix = extra == null ? "" : "：" + truncate(extra);
    return switch (type) {
        case NotificationType.LIKE -> nickname + " 赞了你的视频《" + title + "》";
        case NotificationType.FAVORITE -> nickname + " 收藏了你的视频《" + title + "》";
        case NotificationType.COIN -> nickname + " 给你投了币：《" + title + "》";
        case NotificationType.COMMENT -> nickname + " 评论了你的视频《" + title + "》" + suffix;
        case NotificationType.REPLY -> nickname + " 回复了你的评论" + suffix;
        case NotificationType.FOLLOW -> nickname + " 关注了你";
        default -> nickname + " 和你互动了";
    };
}
```

### 5. 通知的触发点（产生时机）

**互动类（点赞/收藏/投币/评论）** 统一走 `VideoServiceImpl` 的私有方法 `notifyOwner`：查视频归属，作者不是触发者本人时写通知：

```java
private void notifyOwner(Long videoId, Long actorId, int type, String extra) {
    Video video = videoMapper.selectById(videoId);
    if (video != null) {
        notificationService.notify(video.getUserId(), actorId, type, videoId, extra);
    }
}
```

调用点分别在：

- `toggleLike`：点赞成功时 `notifyOwner(videoId, userId, NotificationType.LIKE, null)`；
- `toggleFavorite`：收藏成功时 `notifyOwner(videoId, userId, NotificationType.FAVORITE, null)`；
- `coin`：投币成功后 `notifyOwner(videoId, userId, NotificationType.COIN, null)`；
- `addComment`：一级评论（parent==0）通知视频作者（COMMENT 类型、附评论内容）；楼中楼回复（parent!=0）通知被回复的人：

```java
if (parent == 0) {
    // 一级评论：通知视频作者（自己评论自己的视频不通知）
    notifyOwner(videoId, userId, NotificationType.COMMENT, content);
} else {
    // 楼中楼回复：通知被回复的人（自己回复自己不通知，notify 内部过滤）
    notificationService.notify(parentComment.getUserId(), userId, NotificationType.REPLY, videoId, content);
}
```

**关注类** 在 `FollowServiceImpl.toggleFollow` 中：只有"新建立关系"（insert 成功）才发通知，取关不发：

```java
if (exist == null) {
    UserFollow f = new UserFollow();
    f.setFollowerId(followerId);
    f.setFollowingId(followingId);
    followMapper.insert(f);
    // 关注成功：通知被关注者（内部会过滤"自己关注自己"的情况）
    notificationService.notify(followingId, followerId, NotificationType.FOLLOW, null, null);
    return true;
} else {
    followMapper.deleteById(exist.getId());
    return false;
}
```

### 6. 已读与未读数

- `unreadCount`：`selectCount` 过滤 `user_id = 我 AND is_read = 0`，就是导航栏红点数字；
- `readAll`：用 `LambdaUpdateWrapper` 只更新"未读"记录，避免无谓写操作；
- `readOne`：**归属校验**是关键——`WHERE id = ? AND user_id = 我`，防止把别人的通知标成已读：

```java
@Override
public void readOne(Long userId, Long id) {
    // 归属校验：where user_id = 当前用户，防止把别人的通知标已读
    notificationMapper.update(null, new LambdaUpdateWrapper<UserNotification>()
            .eq(UserNotification::getId, id)
            .eq(UserNotification::getUserId, userId)
            .eq(UserNotification::getIsRead, 0)
            .set(UserNotification::getIsRead, 1));
}
```

四个接口全部需要登录（SecurityConfig 对 `/api/**` 默认拦截，未列在白名单的都要登录）。当前用户从 `SecurityContextHolder` 取出：

### 8. 出参 VO `vo/NotificationVO.java`

在实体基础上补充**触发者昵称**和**视频标题**，前端直接渲染，无需再发联查请求。`NotificationServiceImpl.toVO()` 逐条联查（练习数据量下 N+1 可接受）：

```java
private NotificationVO toVO(UserNotification n) {
    NotificationVO vo = new NotificationVO();
    vo.setId(n.getId());
    vo.setType(n.getType());
    vo.setActorId(n.getActorId());
    vo.setVideoId(n.getVideoId());
    vo.setContent(n.getContent());
    vo.setIsRead(n.getIsRead());
    vo.setCreateTime(n.getCreateTime());
    // 联查触发者昵称（练习场景直接单查，数据量小可接受）
    User actor = n.getActorId() == null ? null : userMapper.selectById(n.getActorId());
    vo.setActorNickname(actor == null ? "匿名用户" : actor.getNickname());
    // 联查视频标题（关注通知没有关联视频）
    if (n.getVideoId() != null) {
        Video video = videoMapper.selectById(n.getVideoId());
        vo.setVideoTitle(video == null ? "" : video.getTitle());
    }
    return vo;
}
```

### 2. 导航栏红点 `frontend/src/components/NavBar.vue`

铃铛只在登录后显示；未读数为 0 时不渲染红点徽标。红点数据来源有两个时机：**登录态变化时立即拉一次**（watch + onMounted），以及 **30 秒定时轮询**兜底（登录态变化、其他设备操作导致的通知都能在 30 秒内反映出来）：

```vue
<!-- 消息铃铛:登录后显示,未读数红点;未登录点击弹登录框 -->
<div v-if="userStore.user" class="bell" @click="goNotification">
  <!-- 铃铛图标（内联 SVG） -->
  <svg viewBox="0 0 24 24" width="22" height="22" fill="currentColor">...</svg>
  <span v-if="unread > 0" class="badge">{{ unread > 99 ? '99+' : unread }}</span>
</div>
```

```javascript
// 拉取未读通知数（登录后显示红点）
async function loadUnread() {
  if (!userStore.user) return
  try {
    const res = await getUnreadCount()
    unread.value = res.data || 0
  } catch {
    unread.value = 0
  }
}

// 登录状态变化时刷新未读数（登录/退出都触发）
watch(() => userStore.user, loadUnread)
onMounted(loadUnread)

// ===== 30s 轮询:两个红点(通知 + 私信)自动更新 =====
let pollTimer = null
onMounted(() => {
  pollTimer = setInterval(() => {
    loadUnread()
    loadDmUnread()
    loadAuditPending()
  }, 30000)
})
onBeforeUnmount(() => {
  if (pollTimer) clearInterval(pollTimer)
})
```

退出登录时显式把红点清零（`handleLogout` 中 `unread.value = 0`、`messageStore.dmUnread = 0`），避免残留旧账号的未读数。

### 3. 通知中心页面 `frontend/src/views/Notification.vue`

- 进入页面拉第一页列表（`size=15`）并刷新未读数；
- **点击通知**：若未读先本地置已读并调 `readNotification(n.id)`（乐观更新），有 `videoId` 则跳转 `/video/detail/{id}`；
- **全部已读**：调 `readAllNotifications()` 后本地把整页 `isRead` 置 1、未读数归零；
- **加载更多**：`hasMore = list.length < total`，翻页追加（`loadPage(false)` 追加，第一页时 `loadPage(true)` 重置）；
- 类型文字映射 `typeText` 与后端常量一致：`{ 1: '点赞', 2: '收藏', 3: '投币', 4: '评论', 5: '回复', 6: '关注' }`。

## 关键设计说明

### 1. "触发点分散 + 写入入口统一"

通知的产生散落在各个互动服务（VideoServiceImpl、FollowServiceImpl），但它们都只调用 `NotificationService.notify()` 这一个入口。好处：文案拼接、防自通知、落库逻辑只维护一份；后续要加"评论被点赞"等新通知类型，只需在新触发点调 `notify()` 并在 `buildContent` 加一个分支。

### 2. "自己通知自己"的静默过滤

`notify()` 第一行就判断 `userId.equals(actorId)` 直接 return。这样触发点无需关心"作者本人操作"的边界情况（自己赞自己的视频、自己评论自己的视频、自己关注自己已被 FollowService 拦截），过滤逻辑收敛在一处。

### 3. 归属校验下沉到 SQL

单条已读的 `WHERE user_id = 我` 是安全关键点：如果只按 `id` 更新，登录用户可以随意把别人的通知标记已读（IDOR 漏洞）。这里把归属条件写进 `LambdaUpdateWrapper`，由数据库保证只能改自己的记录。

### 4. 红点双通道：轮询兜底 + 页面内实时

导航栏红点靠 30 秒轮询（`/unread-count`），不做全局常驻 WebSocket——连接管理复杂，练习项目从简；私信页内的实时性由页面自己的 WS 连接负责（见文档 09）。轮询失败静默保留旧值，等下一轮自愈，不影响页面其他功能。

## 常见问题

### 1. 为什么我点赞自己的视频不会收到通知？

`notify()` 的入口判断 `userId.equals(actorId)` 直接跳过；且 `notifyOwner()` 查出来的作者就是触发者本人，两层都兜住了。这是刻意设计——"自己给自己发通知"没有意义且会污染通知列表。

### 2. 为什么通知文案是后端拼好的，而不是前端拼？

文案格式（昵称 + 动作 + 视频名）在各端要保持一致，且涉及类型到中文动作的映射。放后端拼好存进 `content` 字段，前端只需原样渲染；同时 `content` 落库后即使昵称/视频标题日后变化，历史通知依然保留当时的文案快照。

### 3. 红点数字刷新不及时怎么办？

导航栏每 30 秒轮询一次 `/unread-count`，最多延迟 30 秒。如果用户希望立即刷新，可以刷新页面（进入页面会重新拉取）。练习项目为控制复杂度刻意未做 WebSocket 全站推送，日志与代码注释中均有说明。

### 4. 评论类通知附带的"内容片段"太长怎么办？

`NotificationServiceImpl.truncate()` 会把超过 50 字的评论内容截断并追加"…"，既保留了足够上下文，又避免通知列表被长评论刷屏（表字段 `content` 上限 200 字也与此呼应）。
