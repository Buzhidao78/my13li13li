# 09 前端工程化（Vue3 基建与约定）

## 模块简介

前端工程化文档梳理的是 `frontend/` 的**基础能力层**：axios 统一封装、JWT 存储与注入、路由与守卫、全局状态（用户态/私信红点）、WebSocket 客户端封装、Vite 开发代理，以及与后端的接口约定。这些代码不直接属于某个业务页面，但每个业务页面的请求、跳转、登录判断都依赖它们。

技术栈为 **Vue 3 组合式 API（`<script setup>`）**，无 TypeScript；全局状态用 Vue 内置的 `reactive()` 模块级单例实现（未引入 Pinia，练习项目从简）；接口层按业务拆分为 `src/api/*.js`，统一从 `src/api/request.js` 导出的 axios 实例发请求。

## 功能清单

| 功能 | 说明 | 涉及文件 |
| --- | --- | --- |
| axios 统一封装 | baseURL、请求拦截器注入 token、响应拦截器解包/401 处理 | `src/api/request.js` |
| 业务接口分层 | 按模块拆分接口函数（auth/video/order/dm/notification…） | `src/api/*.js` |
| 路由表与守卫 | 路由懒加载、requiresAuth/requiresAdmin 两级守卫 | `src/router/index.js` |
| 全局用户状态 | token/用户信息存 localStorage，登录弹窗与回跳控制 | `src/store/user.js` |
| 私信红点状态 | 全局未读总数，NavBar 轮询与 Message 页 WS 共同写入 | `src/store/message.js` |
| WebSocket 客户端 | `/ws` 连接、token 传参、指数退避重连、心跳保活 | `src/views/Message.vue` |
| Vite 代理 | /api、/upload/、/ws 三路代理到后端 8080 | `vite.config.js` |
| 后端统一返回 | `Result{code,message,data}`，code=200 为成功 | `backend common/Result.java` |

## 基础设施

本模块为**纯前端基建**，不涉及任何数据库表。它依赖的后端配套包括：

- `backend common/Result.java`：统一返回结构 `{ code, message, data }`；
- `backend config/SecurityConfig.java`：除白名单接口外 `/api/**` 全部要求 JWT 认证，前端据此做 401 处理；
- `backend config/WebSocketConfig.java` + `ws/JwtHandshakeInterceptor.java`：注册 `/ws` 端点，握手阶段校验 `?token=xxx`。

## 前端实现

### 1. 目录结构约定

```
frontend/src/
├── api/        # 接口层：每个文件对应一个后端模块（auth.js、video.js、order.js、dm.js…）
├── router/     # 路由表 + 全局守卫
├── store/      # 全局状态：user.js（登录态）、message.js（私信红点）
├── views/      # 页面组件（Home、VideoDetail、Recharge、Message…）
├── components/ # 公共组件（NavBar、VideoCard、LoginModal…）
└── main.js     # 应用入口：createApp(App).use(router).mount('#app')
```

页面统一使用 `<script setup>` 组合式 API：`ref/computed` 管状态、`onMounted` 拉数据、`watch` 响应登录态变化、`onBeforeUnmount` 清理定时器/WS 连接。

### 2. axios 统一封装 `src/api/request.js`

核心职责三条：**请求自动带 token**、**响应解包 Result**、**401 统一处理**：

```javascript
import axios from 'axios'
import { getToken, clearAuth, userStore } from '../store/user'

/**
 * 统一封装的 axios 实例
 * 职责：
 * 1. 请求自动携带 token（Authorization: Bearer xxx）
 * 2. 响应解包后端 Result { code, message, data }
 * 3. 遇到 401（未登录/token 过期）自动清除登录态并弹出登录框
 */
const request = axios.create({
  baseURL: '/api',
  timeout: 10000
})

// 请求拦截器：每个请求自动带上 token
request.interceptors.request.use((config) => {
  const token = getToken()
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：解包数据 + 统一处理错误
request.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res.code === 200) {
      return res
    }
    // 业务错误：把后端提示 message 变成 Error，调用方用 try/catch 捕获
    return Promise.reject(new Error(res.message || '请求失败'))
  },
  (error) => {
    // HTTP 401：登录失效，清除登录态并弹出登录框
    if (error.response && error.response.status === 401) {
      clearAuth()
      userStore.loginVisible = true
    }
    return Promise.reject(error)
  }
)

export default request
```

业务代码因此很薄：`await request.get('/xxx')` 拿到的直接是 `{ code, message, data }`，取 `res.data` 即可；后端业务错误（如"会员等级不合法"）被转换成 `Error(message)`，页面 `catch (e)` 后直接 `e.message` 展示。

### 3. JWT 存储与注入 `src/store/user.js`

token 与用户信息存 `localStorage`（刷新不丢）；`userStore` 是模块级 `reactive` 单例，用户变化时所有组件自动响应：

```javascript
import { reactive } from 'vue'

const TOKEN_KEY = 'practice2_token'
const USER_KEY = 'practice2_user'

// 从 localStorage 读取缓存的用户信息
function readUser() {
  try {
    return JSON.parse(localStorage.getItem(USER_KEY)) || null
  } catch {
    return null
  }
}

// 全局响应式状态：user 变化时所有组件自动更新
export const userStore = reactive({
  user: readUser(),            // 当前登录用户（null 表示未登录）
  loginVisible: false,         // 是否显示登录弹窗（全局控制）
  redirectTo: null             // 登录成功后要回跳的地址
})

/** 获取 token */
export function getToken() {
  return localStorage.getItem(TOKEN_KEY)
}
/** 保存 token */
export function setToken(token) {
  localStorage.setItem(TOKEN_KEY, token)
}
/** 保存用户信息并更新全局状态 */
export function setUser(user) {
  userStore.user = user
  localStorage.setItem(USER_KEY, JSON.stringify(user))
}
/** 清除登录态（退出登录 / token 过期时调用） */
export function clearAuth() {
  userStore.user = null
  userStore.loginVisible = false
  localStorage.removeItem(TOKEN_KEY)
  localStorage.removeItem(USER_KEY)
}
```

注入流程：登录接口成功后前端调 `setToken(token)` + `setUser(user)`（见 `api/auth.js` 调用方）；之后每个请求由 request.js 拦截器自动加 `Authorization: Bearer {token}` 头。退出登录走 `NavBar.handleLogout()`：先 `clearAuth()` 清态，再**无条件跳回首页**——防止停留在受限页（如审核台）时，换账号登录后"越权看到管理视图"。

### 4. 路由守卫 `src/router/index.js`

路由表分三类：公开页（Home、VideoDetail、Search、UserProfile）、需登录页（`meta.requiresAuth: true`）、管理员页（`meta.requiresAdmin: true`）：

```javascript
const routes = [
  { path: '/', name: 'Home', component: () => import('../views/Home.vue') },
  {
    path: '/recharge', name: 'Recharge',
    component: () => import('../views/Recharge.vue'),
    meta: { requiresAuth: true }          // 会员充值：需登录
  },
  {
    path: '/video/detail/:id', name: 'VideoDetail',
    component: () => import('../views/VideoDetail.vue')   // 播放页：游客可看
  },
  {
    path: '/admin/audit', name: 'Audit',
    component: () => import('../views/Audit.vue'),
    meta: { requiresAuth: true, requiresAdmin: true }     // 审核台：需登录且管理员
  }
  // ... 其余页面
]

/**
 * 全局路由守卫：进入需要登录的页面时检查登录态
 * 练习：后续新增需要登录的页面（如个人中心），加上 meta.requiresAuth: true 即可
 */
router.beforeEach((to) => {
  if (to.meta && to.meta.requiresAuth && !getToken()) {
    // 未登录：记录目标地址并弹出登录框，同时拦截本次跳转（留在当前页）
    // 登录成功后由 LoginModal 读取 redirectTo 自动跳回，实现"登录后回到想去的地方"
    userStore.redirectTo = to.fullPath
    userStore.loginVisible = true
    return false
  }
  if (to.meta && to.meta.requiresAdmin) {
    // 仅管理员（role=1）可访问；非管理员直接拦截回首页（后端 service 也会再校验一次）
    const u = userStore.user
    if (!u || u.role !== 1) {
      alert('仅管理员可访问此页面')
      return { path: '/' }
    }
  }
})
```

登录页是弹窗（`LoginModal.vue`）而非独立路由：未登录访问受限页时守卫记录 `redirectTo` 并弹出登录框，登录成功后自动跳回目标页，实现"登录后回到想去的地方"。

### 6. WebSocket 客户端封装（`src/views/Message.vue`）

与后端 `/ws` 端点对接（原生 `TextWebSocketHandler`，非 STOMP），实现私信实时推送。三个关键点：

- **token 传参**：浏览器 WebSocket API 不能自定义请求头，只能把 token 拼在 URL 上（`/ws?token=xxx`），后端 `JwtHandshakeInterceptor` 在握手阶段校验并拒绝非法连接；
- **指数退避重连**：意外断开后 1s 起重连，每次翻倍封顶 30s；组件卸载主动断开（`wsClosedByMe=true`）不重连；
- **心跳保活**：每 25 秒发 `PING`，防 Vite 代理/网关掐掉空闲连接，回包 `PONG` 直接忽略。

```javascript
let ws = null
let heartbeatTimer = null
let reconnectDelay = 1000        // 重连退避:1s 起,每次翻倍,封顶 30s
let wsClosedByMe = false        // 组件卸载主动断开时不重连

/** 建立 WS 连接(带指数退避重连 + 25s 心跳) */
function connectWs() {
  const token = getToken()
  if (!token) return
  // 走当前域名:开发环境由 Vite 代理 /ws → 8080,生产环境同源部署直连
  const proto = location.protocol === 'https:' ? 'wss' : 'ws'
  ws = new WebSocket(`${proto}://${location.host}/ws?token=${token}`)

  ws.onopen = () => {
    reconnectDelay = 1000 // 连上后重置退避
    startHeartbeat()
  }

  ws.onmessage = (e) => {
    // 心跳回包直接忽略
    if (e.data === 'PONG') return
    try {
      const msg = JSON.parse(e.data)
      if (msg.type === 'DM_NEW') onDmNew(msg.data)
    } catch { /* 非 JSON 帧忽略 */ }
  }

  ws.onclose = () => {
    stopHeartbeat()
    // 意外断开才重连(组件卸载/路由离开时 wsClosedByMe=true)
    if (!wsClosedByMe) {
      setTimeout(connectWs, reconnectDelay)
      reconnectDelay = Math.min(reconnectDelay * 2, 30000)
    }
  }
}

/** 25s 心跳:防止 Vite 代理/网关掐掉空闲连接 */
function startHeartbeat() {
  stopHeartbeat()
  heartbeatTimer = setInterval(() => {
    if (ws && ws.readyState === WebSocket.OPEN) ws.send('PING')
  }, 25000)
}
```

收到 `DM_NEW` 推送后：正在跟对方聊天则直接上屏 + 发已读回执；其他会话则更新会话摘要、未读 +1、全局红点 +1。

### 7. Vite 代理 `vite.config.js`

开发环境三路代理：`/api` 到后端 HTTP、`/upload/` 到静态资源、`/ws` 到 WebSocket。注意 `/upload/` 必须带斜杠，否则会拦截前端自己的路由 `/upload`（投稿页）：

```javascript
export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    // 开发环境代理：前端请求 /api 自动转发到后端 8080
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      },
      // 上传的视频/封面文件：/upload/xxx 转发到后端静态资源
      // 注意用 '/upload/'（带斜杠）而不是 '/upload'，否则会拦截前端路由 /upload（投稿页）
      '/upload/': {
        target: 'http://localhost:8080',
        changeOrigin: true
      },
      // WebSocket：私信实时推送，/ws 转发到后端（ws:true 启用协议升级）
      '/ws': {
        target: 'ws://localhost:8080',
        ws: true
      }
    }
  }
})
```

### 8. 与后端的接口约定

后端所有接口统一返回 `common/Result.java` 包装结构：

```java
@Data
public class Result<T> {
    private Integer code;    // 200 成功；500 业务错误（message 携带中文提示）
    private String message;
    private T data;
}
```

约定细则：

- 前端 axios 的 `baseURL` 为 `/api`，接口路径直接写 `/notification/list` 等；分页接口返回 `IPage`，前端取 `data.records`（当前页数据）与 `data.total`（总条数）；
- 业务失败时后端抛 `BusinessException`，由 `GlobalExceptionHandler` 转成 `code=500` 的 Result；前端响应拦截器将其转为 `Error(message)`，页面 `catch` 展示；
- 未登录/token 过期返回 HTTP 401，前端清除登录态并弹登录框；
- 权限：除 `SecurityConfig` 白名单（如 `/api/auth/**`、视频列表/详情、热搜等）外，其余 `/api/**` 均需登录；管理员接口（如审核）由后端 service 再校验 `role=1`，前端 `requiresAdmin` 守卫只是第一道体验层。

## 关键设计说明

### 1. 状态全部"模块级 reactive 单例"，不引入 Pinia

`store/user.js`、`store/message.js` 直接导出一个 `reactive()` 对象，任何组件 `import { userStore }` 即共享同一份状态，改动自动触发视图更新。对练习项目而言，这比引入 Pinia（依赖注入 + 插件注册）更直观、心智负担更小；当状态量大、需要持久化插件/开发工具时再升级不迟。

### 2. 401 处理的"唯一出口"

登录态失效（token 过期/被篡改/后端重启导致会话丢失）统一在响应拦截器处理：`clearAuth()` + 弹登录框。业务代码完全不需要关心 401——这正是"拦截器收口"的价值。配合路由守卫的 `redirectTo`，用户重新登录后还能回到刚才想去的页面。

### 3. 红点双写入方与"30 秒自愈"

私信红点由轮询（权威值）与 WS 增量（实时性）两个写入方维护，`messageStore.dmUnread` 可能被短暂覆盖（如轮询拿回旧值），但 NavBar 每 30 秒重新拉权威值对齐。这是"实时性与简单性"的折中：不做复杂的消息序号/合并机制，接受短暂偏差。

### 4. WebSocket 与 HTTP 的鉴权通道分离

HTTP 请求把 token 放 `Authorization` 头（走 `JwtAuthenticationFilter`）；WS 握手无法自定义头，token 只能放 URL query（走 `JwtHandshakeInterceptor`），且 `SecurityConfig` 对 `/ws/**` permitAll（握手是普通 HTTP GET，安全链读不到 query 中的 token）。前端 `connectWs` 用 `location.host` 拼地址，开发环境由 Vite 代理 `ws: true` 完成协议升级，生产环境同源直连无需改动。

## 接口约定一览

| 约定项 | 说明 |
| --- | --- |
| 统一返回结构 | `{ code, message, data }`，`code=200` 成功，`code=500` 业务错误（message 为中文提示） |
| 接口前缀 | 前端 `baseURL='/api'`，如 `GET /api/notification/list` |
| 分页约定 | 入参 `page`/`size`；返回 `data.records`（当前页）+ `data.total`（总数） |
| 认证方式 | 请求头 `Authorization: Bearer {token}`；401 时前端清登录态并弹登录框 |
| 权限标记 | 路由 `meta.requiresAuth`（登录）/ `meta.requiresAdmin`（role=1），后端 service 二次校验 |
| 静态资源 | `/upload/xxx` 由后端静态映射提供 |
| WebSocket | 地址 `ws(s)://{host}/ws?token=xxx`，帧格式 `{"type":"DM_NEW","data":{...}}` |

## 常见问题

### 1. 为什么本地访问 `http://localhost:5173/api/xxx` 能通，但直接访问后端接口却跨域？

开发模式页面跑在 Vite 的 5173 端口，浏览器跨域请求被 Vite 代理接管：`/api`、`/upload/`、`/ws` 转发到后端 8080（`changeOrigin` 改写 Host）。浏览器最终看到的是同源请求，自然没有跨域问题；生产环境部署在同源（或网关）下也不涉及跨域。

### 2. 换账号登录后为什么被强制回首页？

`NavBar.handleLogout()` 注释明确说明：若停在退出前页面（如审核台 `/admin/audit`），换一个普通账号登录后仍停留在受限页面，可能造成"越权视图"（普通用户看到管理界面）。统一回首页后，再访问受限页会重新走路由守卫的登录 + 角色校验。这是刻意的安全设计。

### 3. 为什么 WS 用 query 传 token，而不是 Authorization 头？

浏览器的 `new WebSocket(url)` API 不支持设置自定义请求头，token 只能拼在 URL 上（`/ws?token=xxx`）。后端 `JwtHandshakeInterceptor` 在握手阶段解析并校验 token，失败返回 401 拒绝握手；`DmWebSocketHandler` 从握手 attributes 里取 userId 使用。

### 4. WS 断开后页面还能收消息吗？

页面内实时推送依赖 WS；断线期间消息不会丢（发送方已落库），重连成功后会话列表/历史消息会通过 HTTP 重新拉取，未读数由 NavBar 的 30 秒轮询兜底更新。即"实时性降级为轮询"，业务不中断——这正是红点双通道设计的收益。
