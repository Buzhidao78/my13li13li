# 账号认证模块

## 模块简介

账号认证模块是整个仿 B 站视频社区的基础设施，负责「我是谁」这件事：用户注册、登录（账号密码 / 手机验证码）、JWT 签发与校验，以及 Spring Security 过滤链对全站接口的访问控制。

项目采用前后端分离 + 无状态 JWT 架构：登录成功后后端签发一个 token，前端把 token 放在 `Authorization: Bearer xxx` 请求头里随请求携带；后端每个请求经过 `JwtAuthenticationFilter` 解析 token、还原用户、写入 `SecurityContext`，Spring Security 再根据接口规则决定放行还是拦截（未登录 401、无权限 403）。密码使用 BCrypt 单向加密存储，验证码存 Redis（5 分钟有效、60 秒防重复、一次性使用），纯手机号注册的用户也能正常鉴权。

## 功能清单

| 功能 | 说明 | 涉及接口/组件 |
| ---- | ---- | ---- |
| 注册 | 校验用户名/手机号唯一 + 手机验证码 + BCrypt 加密密码入库 | `POST /api/auth/register`，`AuthServiceImpl.register()` |
| 账号密码登录 | 交给 Spring Security `AuthenticationManager` 校验，成功签发 token | `POST /api/auth/login`，`AuthServiceImpl.login()` |
| 手机验证码登录 | 校验 Redis 验证码，用户不存在自动注册 | `POST /api/auth/login/phone`，`AuthServiceImpl.loginByPhone()` |
| 发送短信验证码 | 验证码存 Redis（5 分钟有效、60 秒防重复），练习环境仅打印控制台 | `POST /api/auth/code`，`AuthServiceImpl.sendCode()` |
| 获取当前用户 | 从 `SecurityContext` 取登录用户返回前端（不含密码） | `GET /api/user/me`，`UserController.me()` |
| 接口访问控制 | 公开接口放行、其余 `/api/**` 需登录、角色权限校验 | `SecurityConfig.securityFilterChain()` |
| 统一异常返回 | 业务异常 / 密码错误 / 未知异常转成 `Result` JSON | `GlobalExceptionHandler` |

## 涉及数据表

**`user` 表**（见 `backend/src/main/resources/db/init.sql`）：

| 字段 | 类型 | 作用 |
| ---- | ---- | ---- |
| id | BIGINT 自增 | 主键，JWT 的 subject 存的就是它 |
| username | VARCHAR(50)，唯一 | 用户名（账号密码登录用，纯手机号注册用户可为空） |
| password | VARCHAR(100) | BCrypt 密文（`$2a$12$...`），绝不明文 |
| phone | VARCHAR(20)，唯一 | 手机号（验证码登录用） |
| nickname / avatar / gender / sign | - | 昵称、头像、性别、个性签名 |
| member_level / member_expire | TINYINT / DATETIME | 会员等级与到期时间（会员模块用） |
| role | TINYINT | 0-普通用户 1-管理员（接口层按需校验） |
| status | TINYINT | 0-正常 1-禁用（`LoginUser.isEnabled()` 决定能否登录） |
| deleted | TINYINT | 逻辑删除（MyBatis-Plus 自动过滤） |

建表要点：`UNIQUE KEY uk_username`、`UNIQUE KEY uk_phone` 保证唯一性（注册时先查后插，唯一约束是兜底）；初始数据密码统一为 `123456` 的 BCrypt 密文，管理员 `admin/123456`（role=1）。

## 后端实现

### 1. 认证入口：AuthController

`controller/AuthController.java` 只做参数接收与转发，路由前缀 `/api/auth`：

```java
/** 认证控制器：注册、登录、验证码（这些接口在 SecurityConfig 中已放行，不需要 token） */
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    @Autowired
    private AuthService authService;

    /** 用户注册 */
    @PostMapping("/register")
    public Result<Void> register(@RequestBody RegisterDTO dto) {
        authService.register(dto);
        return Result.success();
    }

    /** 账号密码登录 */
    @PostMapping("/login")
    public Result<LoginVO> login(@RequestBody LoginDTO dto) {
        return Result.success(authService.login(dto));
    }
    // 其余两个端点：loginByPhone（手机验证码登录）、sendCode（发送验证码），见 AuthServiceImpl
}
```

### 2. 注册：唯一性校验 + BCrypt 加密

`AuthServiceImpl.register()` 的流程：校验非空 → 用户名/手机号唯一 → 校验验证码 → 加密密码入库。密码用 `PasswordEncoder`（BCrypt）加密，同一个密码每次加密结果都不同（随机盐），但比对总是能成功：

```java
@Override
public void register(RegisterDTO dto) {
    // 基础校验
    if (!StringUtils.hasText(dto.getUsername()) || !StringUtils.hasText(dto.getPassword())) {
        throw new BusinessException("用户名和密码不能为空");
    }
    // 校验用户名唯一
    Long usernameCount = userMapper.selectCount(
            new LambdaQueryWrapper<User>().eq(User::getUsername, dto.getUsername()));
    if (usernameCount > 0) {
        throw new BusinessException("用户名已存在");
    }
    // 校验手机号唯一
    Long phoneCount = userMapper.selectCount(
            new LambdaQueryWrapper<User>().eq(User::getPhone, dto.getPhone()));
    if (phoneCount > 0) {
        throw new BusinessException("该手机号已被注册");
    }
    // 校验手机号验证码（与验证码登录复用同一个校验逻辑）
    verifyCode(dto.getPhone(), dto.getCode());

    // 组装用户并加密密码
    User user = new User();
    user.setUsername(dto.getUsername());
    user.setPassword(passwordEncoder.encode(dto.getPassword()));
    user.setPhone(dto.getPhone());
    // 昵称默认取手机号后 4 位，方便区分
    user.setNickname(StringUtils.hasText(dto.getNickname())
            ? dto.getNickname()
            : "用户" + dto.getPhone().substring(dto.getPhone().length() - 4));
    user.setGender(0);
    user.setStatus(0);
    userMapper.insert(user);
}
```

### 3. 验证码：存 Redis，5 分钟有效、60 秒防重复、一次性使用

`sendCode()` 用两个 key 实现「限频 + 校验」：`sms:interval:{phone}` 控制 60 秒内不能重复发送；`sms:code:{phone}` 存验证码本体，5 分钟过期。而 `verifyCode()`（私有方法，见源码）从 Redis 取出比对，**校验通过后立即 `delete` 掉 key**，实现「一次性使用」——防止验证码被反复利用：

```java
/** 验证码在 Redis 中的 key 前缀 */
private static final String CODE_PREFIX = "sms:code:";
/** 防重复发送的 key 前缀 */
private static final String INTERVAL_PREFIX = "sms:interval:";

@Override
public void sendCode(String phone) {
    // 1. 防重复发送：60 秒内不能再次发送
    String intervalKey = INTERVAL_PREFIX + phone;
    if (Boolean.TRUE.equals(stringRedisTemplate.hasKey(intervalKey))) {
        throw new BusinessException("发送过于频繁，请 60 秒后再试");
    }
    // 2. 生成 6 位随机验证码
    String code = String.format("%06d", ThreadLocalRandom.current().nextInt(1000000));
    // 3. 验证码存入 Redis，5 分钟有效
    stringRedisTemplate.opsForValue().set(CODE_PREFIX + phone, code, CODE_TTL_MINUTES, TimeUnit.MINUTES);
    // 4. 记录发送间隔，60 秒内禁止再次发送
    stringRedisTemplate.opsForValue().set(intervalKey, "1", SEND_INTERVAL_SECONDS, TimeUnit.SECONDS);
    // 5. 练习环境：仅打印到控制台（生产环境这里接入短信平台真实发送）
    log.info("【验证码】手机号 {} 的验证码为：{}（5 分钟内有效）", phone, code);
}
```

### 4. 账号密码登录：交给 AuthenticationManager

`login()` 把用户名密码包装成 `UsernamePasswordAuthenticationToken` 交给 `AuthenticationManager`，Spring Security 内部会调用 `UserDetailsServiceImpl.loadUserByUsername()` 查用户、再用 `PasswordEncoder.matches()` 比对 BCrypt 密文。失败抛 `BadCredentialsException`（被全局异常处理器转成「用户名或密码错误」），成功则签发 token：

```java
@Override
public LoginVO login(LoginDTO dto) {
    // 1. 构建认证请求（用户名 + 明文密码）
    UsernamePasswordAuthenticationToken authenticationToken =
            new UsernamePasswordAuthenticationToken(dto.getUsername(), dto.getPassword());
    // 2. 交给 AuthenticationManager 校验：
    //    内部会调用 UserDetailsService 查用户 + PasswordEncoder 比对 BCrypt 密码
    //    校验失败会抛 BadCredentialsException（被全局异常处理器转成"用户名或密码错误"）
    Authentication authentication = authenticationManager.authenticate(authenticationToken);
    LoginUser loginUser = (LoginUser) authentication.getPrincipal();
    // 3. 校验通过，签发 token 并返回用户信息
    return buildLoginVO(loginUser);
}
```

### 5. 手机验证码登录：自动注册

`loginByPhone()` 先校验验证码，再按手机号查用户；**查不到就自动注册**（手机号验证码登录的常见做法，降低新用户使用门槛）。没有用户名的用户靠 id 鉴权（见第 7 节）：

```java
@Override
public LoginVO loginByPhone(PhoneLoginDTO dto) {
    // 1. 校验验证码（错误或过期直接抛异常）
    verifyCode(dto.getPhone(), dto.getCode());
    // 2. 按手机号查用户
    User user = userMapper.selectOne(
            new LambdaQueryWrapper<User>().eq(User::getPhone, dto.getPhone()));
    // 3. 用户不存在则自动注册（手机号验证码登录的常见做法）
    if (user == null) {
        user = new User();
        user.setPhone(dto.getPhone());
        user.setNickname("用户" + dto.getPhone().substring(dto.getPhone().length() - 4));
        user.setGender(0);
        user.setStatus(0);
        userMapper.insert(user);
    }
    // 4. 签发 token
    return buildLoginVO(new LoginUser(user));
}
```

### 6. JWT 签发：JwtUtils

`util/JwtUtils.java` 负责生成/解析 token。**subject 存用户 id**（而不是用户名），附带 `username` claim（可为 null）；密钥从配置 `jwt.secret` 生成（HMAC-SHA 签名防篡改），有效期 `jwt.expire` 默认 7 天：

```java
/** 生成 token：subject 存用户 id，方便后续取出 */
public String createToken(Long userId, String username) {
    io.jsonwebtoken.JwtBuilder builder = Jwts.builder()
            // subject 存用户 id，方便后续取出
            .subject(String.valueOf(userId))
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + expire));
    // 用户名可能为 null（纯手机号注册的用户），有值才写入
    if (username != null) {
        builder.claim("username", username);
    }
    return builder.signWith(key()).compact();
}

/** 解析 token，返回载荷（Claims）；token 无效或过期时会抛出异常 */
public Claims parseToken(String token) {
    return Jwts.parser()
            .verifyWith(key())
            .build()
            .parseSignedClaims(token)
            .getPayload();
}
```

### 7. Spring Security 过滤链

**（1）登录用户模型 `LoginUser`**（`security/LoginUser.java`）：实现 `UserDetails`，由 `User` 实体转换而来。两个关键方法：`isEnabled()` 返回 `status == 0`（被禁用账号不允许访问）；`isAdmin()` 返回 `role == 1`（审核等管理操作靠它判断）：

```java
/** 账号是否可用：status 为 0 时可用，为 1（禁用）时不允许登录 */
@Override
public boolean isEnabled() {
    return status != null && status == 0;
}

/** 是否管理员：角色为 1 的管理员，供需要管理员权限的业务（如视频审核）直接判断 */
public boolean isAdmin() {
    return role != null && role == 1;
}
```

**（2）用户查询 `UserDetailsServiceImpl`**：提供两个查询入口——`loadUserByUsername()` 供账号密码登录用；`loadUserById()` 供 JWT 过滤器用。注释说明了为什么按 id 查：**纯手机号验证码注册的用户没有用户名，按用户名查会查不到**：

```java
/**
 * 按用户 id 查用户
 * 说明：JWT 过滤器解析 token 后调用。用 id 而不是用户名，
 * 这样"纯手机号验证码注册"（没有用户名）的用户也能正常鉴权
 */
public UserDetails loadUserById(Long userId) {
    User user = userMapper.selectById(userId);
    if (user == null) {
        throw new UsernameNotFoundException("用户不存在");
    }
    return new LoginUser(user);
}
```

**（3）JWT 过滤器 `JwtAuthenticationFilter`**（`config/JwtAuthenticationFilter.java`）：继承 `OncePerRequestFilter`（每个请求只执行一次），流程是「取 header → 解析 token → 按 id 查用户 → 校验账号可用 → 写入 SecurityContext」：

```java
@Override
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
        throws ServletException, IOException {
    // 1. 从请求头获取 Authorization: Bearer <token>
    String header = request.getHeader("Authorization");
    if (header != null && header.startsWith("Bearer ")) {
        String token = header.substring(7);
        try {
            // 2. 解析 token，取出用户 id（subject 里存的就是用户 id）
            Claims claims = jwtUtils.parseToken(token);
            Long userId = Long.valueOf(claims.getSubject());
            // 3. 按用户 id 查用户（能查到说明账号仍有效）
            UserDetails userDetails = userDetailsService.loadUserById(userId);
            // 4. 校验账号是否可用（被禁用的账号不允许访问）
            if (userDetails.isEnabled()) {
                // 5. 把认证信息放进 SecurityContext，后续接口就能拿到当前用户
                UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
                authentication.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authentication);
            } else {
                SecurityContextHolder.clearContext();
            }
        } catch (Exception e) {
            // token 无效或已过期：不设置认证信息，由 Security 的 401 处理器返回未登录
            SecurityContextHolder.clearContext();
        }
    }
    // 6. 继续执行后续过滤器链
    chain.doFilter(request, response);
}
```

**（4）安全规则 `SecurityConfig`**：无状态（不建 Session、关 CSRF），把认证/放行规则集中定义；`/api/auth/**`、视频公开接口、`/upload/**` 静态资源放行，其余 `/api/**` 一律要求登录；JWT 过滤器加在用户名密码过滤器之前：

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
            // 前后端分离 + JWT 无状态，关闭 CSRF 防护
            .csrf(AbstractHttpConfigurer::disable)
            // 不创建 Session（每次请求都靠 token 识别身份）
            .sessionManagement(session ->
                    session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                    // 登录、注册、发验证码等接口放行（不需要 token）
                    .requestMatchers("/api/auth/**").permitAll()
                    // 测试用的 hello 接口放行
                    .requestMatchers("/api/user/hello").permitAll()
                    // 视频模块：已发布列表/搜索/详情/播放计数/评论列表公开（游客可看）；上传/我的/互动需登录
                    .requestMatchers("/api/video/list",
                            "/api/video/search",
                            "/api/video/user/**",
                            "/api/video/detail/**",
                            "/api/video/*/play",
                            "/api/video/*/comments").permitAll()
                    // 上传的视频文件静态资源放行（/upload/**）
                    .requestMatchers("/upload/**").permitAll()
                    // 其他所有 /api/** 接口都必须登录后才能访问
                    .anyRequest().authenticated())
            // 异常处理：未登录返回 401，无权限返回 403
            .exceptionHandling(exception -> exception
                    .authenticationEntryPoint(restAuthenticationEntryPoint)
                    .accessDeniedHandler(restAccessDeniedHandler))
            // 在用户名密码过滤器之前执行 JWT 过滤器，先校验 token
            .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
    return http.build();
}
```

**（5）401 / 403 统一 JSON**：Spring Security 在进入 Controller 之前就拦截了请求，**全局 `@RestControllerAdvice` 管不到**，所以必须用两个专用 Handler 输出 JSON。`RestAuthenticationEntryPoint` 返回 401「未登录或登录已过期」，`RestAccessDeniedHandler` 返回 403「没有权限访问」。

### 8. 全局异常处理

`common/GlobalExceptionHandler.java` 把异常统一转成 `Result`：`BusinessException`（业务提示）、`BadCredentialsException`（密码错误，不暴露堆栈）、`Exception` 兜底（记日志 + 「系统繁忙」）：

```java
/** 账号密码错误（Spring Security 抛出）：给出友好的提示，不暴露堆栈 */
@ExceptionHandler(BadCredentialsException.class)
public Result<Void> handleBadCredentialsException(BadCredentialsException e) {
    return Result.error("用户名或密码错误");
}
```

### 9. 当前用户获取

`UserController.me()` 演示了如何从 `SecurityContext` 取当前登录用户（`LoginUser`），再通过 `UserVO.from()` 转成安全 VO（只返回 id/用户名/昵称/头像等，**绝不包含密码**）：

```java
/** 获取当前登录用户信息（需要 token，验证 JWT 过滤器是否生效） */
@GetMapping("/me")
public Result<UserVO> me() {
    // 登录后，JwtAuthenticationFilter 会把 LoginUser 放进 SecurityContext
    LoginUser loginUser = (LoginUser) SecurityContextHolder.getContext().getAuthentication().getPrincipal();
    return Result.success(UserVO.from(loginUser));
}
```

## 前端实现

### 1. API 封装

`frontend/src/api/auth.js` 是对后端四个认证接口的封装；`frontend/src/api/request.js` 是统一 axios 实例——请求拦截器自动拼 `Authorization: Bearer <token>`，响应拦截器解包 `Result`、遇到业务错误抛 Error，遇到 **HTTP 401 自动清除登录态并弹出登录框**：

```js
// 请求拦截器：每个请求自动带上 token
request.interceptors.request.use((config) => {
  const token = getToken()
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：解包数据 + 统一处理错误
request.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res.code === 200) {
      return res
    }
    // 业务错误：把后端提示 message 变成 Error，调用方用 try/catch 捕获
    return Promise.reject(new Error(res.message || '请求失败'))
  },
  (error) => {
    // HTTP 401：登录失效，清除登录态并弹出登录框
    if (error.response && error.response.status === 401) {
      clearAuth()
      userStore.loginVisible = true
    }
    return Promise.reject(error)
  }
)
```

### 2. 登录弹窗 LoginModal.vue

三个 Tab（密码登录 / 验证码登录 / 注册），`store/user.js` 里的 `userStore` 是全局响应式登录态（token 与用户信息存 localStorage，刷新不丢失）。登录成功后 `onLoginSuccess` 保存 token 与用户、关闭弹窗，并按 `userStore.redirectTo` 跳回之前被拦截的目标页（如投稿页）：

```js
/** 登录成功后的公共处理：保存 token + 用户信息 + 关闭弹窗 */
function onLoginSuccess(data) {
  setToken(data.token)
  setUser(data.user)
  close()
  // 若之前在访问需登录的页面（如投稿/充值）时被路由守卫拦截，登录后自动跳回目标页
  const target = userStore.redirectTo
  userStore.redirectTo = null
  if (target) {
    router.push(target)
  }
}
```

发送验证码后前端启动 60 秒倒计时（`countdown`），与后端 `sms:interval` 60 秒限频呼应。`router/index.js` 的路由守卫 `beforeEach` 检查 `meta.requiresAuth` / `meta.requiresAdmin`，未登录记录 `redirectTo` 并弹出登录框，非管理员访问 `/admin/audit` 直接拦截回首页。

## 关键设计说明

**1. 为什么 JWT 无状态，但每次请求还查一次库？**

纯无状态 JWT 可以直接信任 token 里的信息，但无法感知「账号被禁用」。本项目的 `JwtAuthenticationFilter` 解析 token 后仍调用 `loadUserById()` 查库，并用 `isEnabled()` 判断——代价是每次请求多一次 DB 查询（练习规模可接受），换来「管理员封号立即生效」的能力。

**2. 验证码为什么存 Redis 而不是数据库？**

三个原因：一是**天然过期**——`SET key code EX 300` 一条命令搞定 5 分钟有效期，无需定时清理任务；二是**原子防重**——`sms:interval` key 存在即拒绝，天然防刷；三是**一次性使用**——`verifyCode()` 校验后立刻 `delete`。若存数据库，过期/防重/删除都需要额外代码。

**3. 为什么登录按用户名、鉴权按用户 id？**

账号密码登录的输入是「用户名 + 密码」，所以 `UserDetailsService` 按用户名查；但 JWT 的 subject 存的是用户 id，因为**纯手机号验证码注册的用户没有用户名**（`username` 字段为空），token 里存用户名会导致这类用户无法鉴权。`loadUserById()` 的存在正是为了兼容这条链路。

**4. 为什么 401/403 不走全局异常处理器？**

`@RestControllerAdvice` 只能捕获进入 DispatcherServlet 后抛出的异常；Spring Security 的过滤器在 Controller 之前就拦截了未认证请求，异常根本到不了 Controller。因此必须用 `AuthenticationEntryPoint`（401）和 `AccessDeniedHandler`（403）直接写与 `Result` 同构的 JSON，前端拦截器才能按统一格式处理。

## 常见问题

**Q1：验证码登录时，两个人同时用同一个手机号注册怎么办？**

`uk_phone` 唯一约束兜底：并发下两个请求都通过了「先查后插」，第二个 insert 会抛 `DuplicateKeyException`（数据库唯一键冲突），被全局异常处理器兜底为「系统繁忙」。生产项目可捕获该异常并转成「手机号已被注册」的友好提示。

**Q2：登录接口会不会被暴力破解？**

当前实现依赖 BCrypt（计算代价高、每次加密结果不同）抵抗彩虹表，但没有验证码/锁定等防爆破手段。`LoginUser.isEnabled()` 已支持账号禁用，可在登录失败计数超限后把 `status` 置 1 实现锁定，这是后续可扩展点。

**Q3：token 过期了前端怎么处理？**

后端解析 token 抛异常 → `JwtAuthenticationFilter` 清空上下文 → 未认证请求命中 `RestAuthenticationEntryPoint` 返回 401 JSON → 前端 axios 响应拦截器捕获 401 → `clearAuth()` 清除本地登录态 + `userStore.loginVisible = true` 弹出登录框，用户重新登录即可，全程无感刷新页面。

> 补充：管理员权限靠 `LoginUser.isAdmin()`（role==1）控制，如视频审核 `audit()` 会先在 service 层校验管理员身份，防止任意登录用户越权。
