# 06 个人中心

> 配套项目：my13li13li（Spring Boot 3.2 后端 + Vue3 前端）
> 本文档讲解仿 B 站社区的**个人中心**与**用户主页**模块：我的视频（下架/重新上架/删除）、我的收藏、观看历史（写入/分页/删除）、关注/粉丝列表，以及用户主页资料统计与会员信息展示。

---

## 模块简介

本项目把"人的页面"分成两个视角：

1. **他人主页（公开）**：`/user/:id` 对应 `GET /api/user/{userId}/profile` + `GET /api/video/user/{userId}` + 粉丝/关注列表。展示资料、统计（视频数/粉丝数/关注数）、互关标识，游客可看。
2. **我的中心（需登录）**：`/user/center` 对应 `UserCenterController`（`/api/user/me/**`）与 `GET /api/video/my`。五个 Tab：**我的视频 / 我的收藏 / 观看历史 / 我的关注 / 我的粉丝**，并提供视频管理操作（下架、重新上架、删除）与会员信息展示。

数据层面，个人中心聚合了多张关系表：`video`（我的视频）、`video_favorite`（收藏）、`watch_history`（观看历史）、`user_follow`（关注/粉丝）。其中"我的收藏/我的观看历史"由 `UserCenterController` 转发给 `VideoService` 处理——因为二者都是"用户-视频"关系，复用视频模块的 VO 转换最合适。

观看历史的写入时机在播放计数接口：`POST /api/video/{id}/play` 被调用时，登录用户顺带写入一条历史（同视频只留一条，重复观看只更新时间）。

## 涉及数据表

### watch_history（观看历史表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键，自增 |
| video_id | BIGINT | 看过的视频 |
| user_id | BIGINT | 观看用户 |
| watch_time | DATETIME | 最近观看时间 |

建表要点：

- `UNIQUE KEY uk_video_user (video_id, user_id)`：**同一用户对同一视频只留一条历史**——重复观看走"更新 watch_time"而不是新增记录；
- `INDEX idx_user_time (user_id, watch_time)`：观看历史列表 `WHERE user_id=? ORDER BY watch_time DESC` 命中索引。

### video_favorite（视频收藏表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键，自增 |
| video_id / user_id | BIGINT | 收藏的视频 / 收藏的用户 |
| create_time | DATETIME | 收藏时间 |

建表要点：`UNIQUE KEY uk_video_user (video_id, user_id)` 防重复收藏；`INDEX idx_user (user_id)` 支撑"我的收藏"列表。

### video 表（我的视频）

关注 `status` 状态机：`0待审核 1已发布 2已驳回 3已下架`（见 `VideoStatus` 常量类）。"我的视频"列表展示**所有状态**（区别于他人主页只看已发布），前端按状态渲染徽章与可用操作。

### user 表（会员信息）

关注 `member_level`（0普通 1白银 2黄金 3钻石）与 `member_expire`（会员到期时间，NULL 表示从未开通）。`MemberInfoVO.isMember` 的判断依据是"到期时间在未来才算有效"，并非等级 > 0。

## 后端实现

### 1. 用户主页资料与统计（FollowServiceImpl.profile + UserProfileVO）

主页接口虽然挂在 `FollowController`（路径 `/api/user/{userId}/profile`），但核心字段是关注模块的"是否已关注/是否互关"，代码注释明确说明了放在这里的理由。统计数字全部实时 `selectCount`：

```java
UserProfileVO vo = new UserProfileVO();
vo.setId(user.getId());
vo.setNickname(user.getNickname());
vo.setAvatar(user.getAvatar());
vo.setSign(user.getSign());
vo.setGender(user.getGender());
// 统计：已发布视频数（他人主页只看已发布，待审核/驳回不展示）
vo.setVideoCount(videoMapper.selectCount(new LambdaQueryWrapper<Video>()
        .eq(Video::getUserId, targetUserId)
        .eq(Video::getStatus, VideoStatus.PUBLISHED)));
// 统计：粉丝数 = 关注了这个人的记录数；关注数 = 这个人关注别人的记录数
vo.setFollowerCount(followMapper.selectCount(new LambdaQueryWrapper<UserFollow>()
        .eq(UserFollow::getFollowingId, targetUserId)));
vo.setFollowingCount(followMapper.selectCount(new LambdaQueryWrapper<UserFollow>()
        .eq(UserFollow::getFollowerId, targetUserId)));
// 当前登录用户是否已关注（未登录不查，返回 null）
vo.setFollowed(currentUserId == null ? null : isFollowed(currentUserId, targetUserId));
// 是否互相关注（仅登录且看别人时有意义，私信抖音规则豁免也依赖这个判定）
vo.setMutualFollowed(currentUserId == null || currentUserId.equals(targetUserId)
        ? null : isMutualFollowed(currentUserId, targetUserId));
```

### 2. 我的视频 + 下架 / 重新上架 / 删除（VideoServiceImpl）

**列表**：查所有状态、按创建时间倒序（前端负责渲染状态徽章）：

```java
@Override
public IPage<VideoVO> listMy(Long userId, long page, long size) {
    Page<Video> p = videoMapper.selectPage(new Page<>(page, size),
            new LambdaQueryWrapper<Video>()
                    .eq(Video::getUserId, userId)
                    .orderByDesc(Video::getCreateTime));
    return p.convert(this::toVO);
}
```

**下架 / 重新上架**是一对互逆操作，核心是**状态机校验 + 作者或管理员权限**：

```java
@Override
public void offline(Long id, Long operatorId) {
    Video video = videoMapper.selectById(id);
    if (video == null) throw new BusinessException("视频不存在");
    requireOwnerOrAdmin(video, operatorId);          // 作者本人或管理员
    if (!video.getStatus().equals(VideoStatus.PUBLISHED)) {
        throw new BusinessException("只有已发布的视频才能下架");
    }
    Video update = new Video();
    update.setId(id);
    update.setStatus(VideoStatus.OFFLINE);
    videoMapper.updateById(update);
}

@Override
public void republish(Long id, Long operatorId) {
    // ... 同样 requireOwnerOrAdmin
    if (!video.getStatus().equals(VideoStatus.OFFLINE)) {
        throw new BusinessException("只有已下架的视频才能重新上架");
    }
    // status 改为 PUBLISHED
}
```

**删除**是事务方法：硬删除视频并**级联清理**评论/收藏/历史/投币/通知 + Redis 计数 + 磁盘文件，避免留下孤儿数据：

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void deleteVideo(Long id, Long operatorId) {
    // ... 存在性校验 + requireOwnerOrAdmin
    // 级联清理互动数据：评论/收藏/观看历史/投币/关联通知
    commentMapper.delete(new LambdaQueryWrapper<VideoComment>().eq(VideoComment::getVideoId, id));
    favoriteMapper.delete(new LambdaQueryWrapper<VideoFavorite>().eq(VideoFavorite::getVideoId, id));
    historyMapper.delete(new LambdaQueryWrapper<WatchHistory>().eq(WatchHistory::getVideoId, id));
    coinMapper.delete(new LambdaQueryWrapper<VideoCoin>().eq(VideoCoin::getVideoId, id));
    notificationMapper.delete(new LambdaQueryWrapper<UserNotification>().eq(UserNotification::getVideoId, id));
    videoMapper.deleteById(id);
    // 清理 Redis 中的计数/点赞集合（否则残留 key 会让 detail 显示过期计数）
    stringRedisTemplate.delete(KEY_PLAY + id);
    stringRedisTemplate.delete(KEY_LIKE + id);
    stringRedisTemplate.delete(KEY_LIKE_COUNT + id);
    // 清理磁盘文件：视频本体 + 封面（失败仅记日志，不影响主流程）
    uploadUtils.deleteIfExists(video.getVideoUrl());
    uploadUtils.deleteIfExists(video.getCoverUrl());
}
```

### 3. 观看历史：播放时写入（VideoServiceImpl.recordPlay）

`POST /api/video/{id}/play` 是公开接口，登录用户会顺带写历史。写入的核心技巧：**先插后捕异常**，用唯一约束冲突判断"之前看过"：

```java
@Override
public void recordPlay(Long videoId, Long userId) {
    Video video = videoMapper.selectById(videoId);
    if (video == null || !video.getStatus().equals(VideoStatus.PUBLISHED)) {
        throw new BusinessException("视频不存在或未发布");
    }
    // 1. 播放量：Redis 原子自增（高并发下 INCR 不会丢，定时任务再刷进 MySQL）
    stringRedisTemplate.opsForValue().increment(KEY_PLAY + videoId);

    // 2. 登录用户记录观看历史（同一视频只保留一条，重复看只更新时间）
    if (userId != null) {
        WatchHistory history = new WatchHistory();
        history.setVideoId(videoId);
        history.setUserId(userId);
        history.setWatchTime(LocalDateTime.now());
        try {
            historyMapper.insert(history);
        } catch (DuplicateKeyException e) {
            // 唯一约束冲突 = 之前看过，更新观看时间
            WatchHistory exist = historyMapper.selectOne(new LambdaQueryWrapper<WatchHistory>()
                    .eq(WatchHistory::getVideoId, videoId)
                    .eq(WatchHistory::getUserId, userId));
            if (exist != null) {
                exist.setWatchTime(LocalDateTime.now());
                historyMapper.updateById(exist);
            }
        }
    }
}
```

列表实现有个共同的健壮性处理——**视频已被删除（作者删稿）的记录自动跳过**，避免空指针/脏数据展示：

```java
@Override
public IPage<VideoVO> myFavorites(Long userId, long page, long size) {
    Page<VideoFavorite> p = favoriteMapper.selectPage(new Page<>(page, size),
            new LambdaQueryWrapper<VideoFavorite>()
                    .eq(VideoFavorite::getUserId, userId)
                    .orderByDesc(VideoFavorite::getCreateTime));
    // 逐条联查视频：视频已被删除（作者删稿）的记录自动跳过，避免空指针/脏数据展示
    List<VideoVO> vos = new ArrayList<>();
    for (VideoFavorite f : p.getRecords()) {
        Video video = videoMapper.selectById(f.getVideoId());
        if (video == null) continue;
        VideoVO vo = toVO(video);
        vo.setInteractTime(f.getCreateTime());   // 收藏时间回填到 VO，前端显示"收藏于 xx"
        vos.add(vo);
    }
    Page<VideoVO> result = new Page<>(p.getCurrent(), p.getSize(), p.getTotal());
    result.setRecords(vos);
    return result;
}
```

`myHistory` 逻辑与 `myFavorites` 完全对称（查 `watch_history` 表、回填 `watch_time` 为 `interactTime`）。删除单条历史按"用户+视频"双条件定位（一个用户对同一视频只会有一条记录）：

```java
@Override
public void deleteHistory(Long userId, Long videoId) {
    historyMapper.delete(new LambdaQueryWrapper<WatchHistory>()
            .eq(WatchHistory::getUserId, userId)
            .eq(WatchHistory::getVideoId, videoId));
}
```

"我的视频"Tab 的行内操作按 `status` 显隐：`status===1` 显示"下架"、`status===3` 显示"重新上架"、恒显示"删除"（删除需**两次 confirm** 二次确认）。删除/取消收藏后用 `reloadAfterRemove` 刷新，若删掉的是本页最后一条则回退一页：

```js
async function onDeleteVideo(v) {
  if (!window.confirm(`确定删除《${v.title}》吗？删除后不可恢复！`)) return

  try {
    await deleteVideo(v.id)
    await reloadAfterRemove()
  } catch (e) { window.alert(e.message || '删除失败') }

/** 删除/取消收藏后刷新当前页；若删掉的是本页最后一条则回退一页，避免停在空页 */
async function reloadAfterRemove() {
  await loadPage()
  if (list.value.length === 0 && page.value > 1) {
    page.value--
    await loadPage()
  }
}
```

## 关键设计说明

**① 观看历史为什么"先 insert 再捕获 DuplicateKeyException"而不是"先查询再插入"？**
`recordPlay` 是播放时高频调用。先查再插存在竞态：两个请求同时查到"不存在"，都去 insert，其中一个必然撞唯一约束失败。项目选择"直接 insert + 捕获 `DuplicateKeyException` 回退为 update"——利用数据库唯一约束做最终裁决，逻辑最简洁且在高并发下行为正确。练习项目直接抛异常捕获即可；真实高并发场景会改用 `INSERT ... ON DUPLICATE KEY UPDATE` 一条 SQL 原子完成。

**② 收藏/历史列表里"视频已删除就跳过"的意义是什么？**
`video` 表是硬删除（`deleteVideo` 直接 `deleteById`），所以收藏/历史记录可能指向不存在的视频。如果直接 `toVO(video)` 会 NPE 或把脏数据展示给用户。跳过策略让列表**自动收敛**：作者删稿后，收藏/历史里对应条目自然消失（无需级联清理历史表——虽然 `deleteVideo` 也会顺手清理）。这是"展示层防御 + 写路径清理"的双保险。

**③ "我的视频"和"他人主页视频"为什么要两套接口？**
- `GET /api/video/my`：**所有状态**（含待审核/驳回/下架），因为作者需要管理自己的全部视频（下架、重新上架、查看审核进度），需登录；
- `GET /api/video/user/{userId}`：**只看已发布**，因为对他人而言"草稿/被驳回"是私密信息，公开接口（游客可看）只暴露已发布内容。

同一个 `VideoStatus` 状态机，两个查询用 `eq(status, PUBLISHED)` 与"不筛状态"两种写法表达不同的可见性边界。

**④ 会员信息为什么不直接读 user 表字段，而要经 OrderService？**
`user` 表确实有 `member_level` / `member_expire` 字段，但"是否有效会员"（到期时间是否在未来）与"剩余天数"的计算逻辑属于会员订单域的规则（充值后由订单模块更新），个人中心复用 `OrderService.getMemberInfo` 可以保证**所有读取方拿到同一份口径**，避免前端各自算、口径不一致。前端只在 `isMember=true` 时渲染会员行，普通用户（等级 0）不展示，避免"未开通过会员"的冗余信息。

|---|---|---|---|
| GET | /api/user/{userId}/profile | 用户主页（资料+统计+关注/互关标识） | 公开 |
| GET | /api/video/user/{userId} | 某用户已发布的视频（分页） | 公开 |
| GET | /api/follow/{userId}/followers | 粉丝列表（带互关标识） | 公开 |
| GET | /api/follow/{userId}/following | 关注列表（带互关标识） | 公开 |
| GET | /api/video/my | 我的视频（所有状态，分页） | 登录 |
| POST | /api/video/{id}/offline | 下架（仅已发布；作者或管理员） | 登录 |
| POST | /api/video/{id}/republish | 重新上架（仅已下架；作者或管理员） | 登录 |
| DELETE | /api/video/{id} | 删除视频（硬删除 + 级联清理） | 登录 |
| GET | /api/user/me/favorites | 我的收藏（按收藏时间倒序） | 登录 |
| GET | /api/user/me/history | 观看历史（按观看时间倒序） | 登录 |
| DELETE | /api/user/me/history/{videoId} | 删除单条观看历史 | 登录 |
| POST | /api/video/{id}/play | 播放计数（登录用户顺带写观看历史） | 公开 |
| GET | /api/member/info | 当前用户会员信息（等级/到期/剩余天数） | 登录 |

## 常见问题

**Q1：为什么我在"我的视频"里看不到刚上传的视频？**
能看到，但状态是"待审核(0)"徽章。`listMy` 返回所有状态。若想出现在**首页/他人主页/搜索结果**里，需要管理员在审核台通过（变为"已发布"）；被驳回(2)的视频也只有作者本人可见。

**Q2：取消收藏/删除历史后，分页可能停在空白页？**
前端 `reloadAfterRemove` 已处理：删除成功后重新加载当前页，如果当前页变空且页码 > 1，自动回退一页再加载。关注/粉丝 Tab 的"删除"不存在（取消关注在他人主页操作），所以该兜底只影响视频类 Tab。

**Q3：看过的视频被作者删除后，观看历史里会怎样？**
后端 `myHistory` 对"视频已不存在"的记录直接跳过（不渲染），前端看不到脏条目；同时 `deleteVideo` 的事务里也会 `historyMapper.delete` 级联清理。两者叠加保证历史列表始终干净。收藏同理。

**Q4：为什么我的观看历史在"重复看同一个视频"后只有一条？**
`watch_history` 有 `UNIQUE KEY uk_video_user (video_id, user_id)`。`recordPlay` 首次观看 insert，再次观看命中唯一约束冲突后**只更新 watch_time**（DuplicateKeyException 分支），所以列表里始终只有一条、且排序会因时间更新而置顶——这正是"观看历史"的直觉行为（最近看的在前面，同视频不重复）。
