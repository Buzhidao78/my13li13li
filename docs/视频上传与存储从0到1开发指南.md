# 视频上传与存储从 0 到 1 开发指南

> 配套项目：practice2（Spring Boot 3.2 + Vue3）
> 本模块是"视频社区站"路线图的**模块 1：视频上传与存储**。
> 本文档讲解该模块如何从 0 到 1 写出来：**开发路线、核心知识点、两个真实踩过的坑**。
> 做完本模块，你能在浏览器里完成"上传视频 → 审核通过 → 播放详情"的完整闭环。

---

## 0. 功能总览：这个模块练什么？

**功能**：登录用户上传视频（标题 + 文件 + 封面 + 分类）→ 默认"待审核"→ 审核通过后进入公开列表 → 任何人可打开详情页播放。

**和之前模块最大的不同**：这是项目第一次处理**文件**（非结构化数据）。之前的登录、订单全是"字符串/数字"，而视频是"二进制大文件"——存哪、怎么访问、怎么限制大小，都是新问题。

**做完整闭环需要解决的三件事**：

| 问题 | 答案（本模块的方案） |
|---|---|
| 视频文件存哪？ | 本地磁盘 `./upload/按日期/随机名.mp4` |
| 浏览器怎么访问到文件？ | 后端静态资源映射 `/upload/**` → 磁盘目录 |
| 上传后谁可见？ | 状态机控制：待审核(0) → 已发布(1) / 已驳回(2)，未发布仅作者可见 |

---

## 1. 开发路线（按依赖顺序）

```
① 想清楚设计（存储方案 + 状态机 + 路径规则）   ← 最容易被跳过但最重要
② 建表 + 状态常量                              ← 数据模型
③ 实体 / Mapper / 上传工具类 UploadUtils      ← 核心：校验 + 存盘
④ Service 接口 + 实现                         ← 业务：状态机、权限
⑤ Controller + 接口设计                       ← 入口
⑥ 静态资源映射（WebConfig）+ Security 放行     ← 让文件能被访问
⑦ 前端：API 封装 → 上传页 → 详情页 → 路由     ← 界面
⑧ 浏览器验证闭环
```

### 第 0 步：先想清楚三个设计决策（这一步决定后面所有代码）

**决策 1：文件存本地磁盘，不引入云存储**
视频文件本质是"一堆二进制字节"。入门阶段最直接的方案：存后端服务器本地磁盘。配置写在 `application.yml`，将来换成 MinIO/OSS 只改存储实现，其他不动。

**决策 2：视频状态机（内容审核的前提）**

```
上传时:                待审核(0)
审核时: 待审核 ──通过──▶ 已发布(1)
        待审核 ──驳回──▶ 已驳回(2)（仅作者可见）
运营时: 已发布 ──下架──▶ 已下架(3)
```

**决策 3：存储路径和访问路径分离**
- 磁盘真实路径：`./upload/20260907/随机名.mp4`（按日期分目录）
- 对外访问路径：`/upload/20260907/随机名.mp4`（数据库存这个，浏览器直接访问）

> **为什么分离？** 数据库里存"访问路径"而不是"磁盘路径"，好处是磁盘目录随便改，前端无感知；访问路径由后端统一生成，还能控制文件名不暴露。

### 第 1 步：建表 + 状态常量

`video` 表核心字段：标题、简介、两个文件路径、分类、**状态**、四个计数（播放/点赞/收藏/投币，本模块先落库，互动在模块 3 做）。

```java
/** 视频状态常量：用常量而不是魔法数字 0/1/2 */
public final class VideoStatus {
    public static final int PENDING = 0;   // 待审核
    public static final int PUBLISHED = 1; // 已发布
    public static final int REJECTED = 2;  // 已驳回
    public static final int OFFLINE = 3;   // 已下架
}
```

> **为什么用常量类？** 业务代码里出现 `video.getStatus().equals(VideoStatus.PUBLISHED)` 比 `equals(1)` 可读得多，改状态值也只需改一处。

### 第 2 步：上传工具类 UploadUtils（本模块的核心）

所有上传都走这个工具：**校验 → 生成路径 → 存盘 → 返回访问路径**。

```java
@Slf4j
@Component
public class UploadUtils {

    /** 上传根目录：从配置文件读（将来换 MinIO 只需改这里） */
    @Value("${file.upload-dir:./upload}")
    private String uploadDir;

    /** 白名单：只允许这些扩展名（防恶意文件上传） */
    private static final List<String> VIDEO_EXTS = List.of("mp4", "webm", "mov", "avi");

    public String saveVideo(MultipartFile file) {
        return save(file, VIDEO_EXTS, 100L * 1024 * 1024); // 视频 ≤100MB
    }

    private String save(MultipartFile file, List<String> allowExts, long maxSize) {
        // 1. 空文件校验
        // 2. 扩展名校验：从原始文件名取扩展名，必须命中白名单
        // 3. 大小校验：超过上限直接拒绝
        // 4. 生成目录 {uploadDir}/{yyyyMMdd}/，不存在就创建
        // 5. 生成唯一文件名：UUID + 扩展名（避免重名覆盖）
        // 6. 写入磁盘：Files.copy（读输入流写目标文件）
        // 7. 返回访问路径：/upload/20260907/随机名.mp4
    }
}
```

**三个必须懂的设计：**

**① 白名单校验 vs 只查扩展名**：校验扩展名是"防君子不防小人"（恶意用户可改名），但这是上传安全的第一道闸，必须做；更严格的 MIME/内容校验留到进阶。**绝不信任用户传的路径和名字，文件名必须由后端重新生成。**

**② 为什么用 UUID 做文件名？** 如果直接用用户文件名（比如 `我的视频.mp4`），两个用户传同名文件会互相覆盖。UUID 保证全球唯一，且能挡住路径穿越攻击（`../../etc/passwd` 这种）。

**③ `Files.copy` 而不是 `transferTo`**：`MultipartFile.transferTo()` 在不同 Servlet 容器下行为不一致（有的直接 move，失败就报错），`Files.copy(输入流, 目标路径)` 行为稳定可控，还方便加 `REPLACE_EXISTING`。**这是我们开发时真实踩到的坑，详见"踩坑 1"。**

### 第 3 步：Service 接口 + 实现（业务规则在这里）

**接口定义**（先想清楚"这个模块对外提供哪些能力"）：

```java
VideoVO upload(Long userId, MultipartFile file, MultipartFile cover,
               String title, String description, Integer category);
IPage<VideoVO> list(long page, long size, Integer category);       // 已发布列表（公开）
VideoVO detail(Long id, Long currentUserId);                       // 详情（带权限判断）
IPage<VideoVO> listMy(Long userId, long page, long size);          // 我的视频
void audit(Long id, int status);                                   // 审核（状态机）
```

**实现里两个重点：**

**① 上传默认"待审核"**（状态机入口）：
```java
video.setStatus(VideoStatus.PENDING);
videoMapper.insert(video);
```

**② 详情页的权限判断**（未发布的视频只有作者能看到）：
```java
boolean published = video.getStatus().equals(VideoStatus.PUBLISHED);
boolean isOwner = currentUserId != null && currentUserId.equals(video.getUserId());
if (!published && !isOwner) {
    throw new BusinessException("视频未发布，仅作者可见");
}
```

**③ 审核的状态机校验**（非法流转直接拒绝）：
```java
if (!video.getStatus().equals(VideoStatus.PENDING)) {
    throw new BusinessException("只有待审核的视频才能审核");
}
if (status != VideoStatus.PUBLISHED && status != VideoStatus.REJECTED) {
    throw new BusinessException("审核状态不合法");
}
```

### 第 4 步：Controller + 接口设计

**接口清单**（RESTful）：

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/video/upload` | 上传视频（multipart） | 登录 |
| GET | `/api/video/list` | 已发布列表（分页） | 公开 |
| GET | `/api/video/detail/{id}` | 详情（未发布仅作者） | 公开 |
| GET | `/api/video/my` | 我的视频 | 登录 |
| POST | `/api/video/{id}/audit?status=1` | 审核 | 登录 |

**两个接口设计细节：**

**① 上传用 `multipart/form-data`，不用 JSON**：JSON 只能传文本，视频是二进制文件，必须用 multipart。Controller 里用 `@RequestParam("file") MultipartFile file` 接收。

**② 为什么详情用 `/detail/{id}` 而不是 `/api/video/{id}`？** 为了和 `/my`、`/upload` 精确区分，让 Spring Security 能"只放行公开的、精确锁定要登录的"：

```java
// SecurityConfig：只放行这两个，其余 /api/video/** 都要登录
.requestMatchers("/api/video/list", "/api/video/detail/**").permitAll()
.requestMatchers("/upload/**").permitAll()   // 静态文件公开
```

> 如果用 `/api/video/{id}`，`/api/video/my` 也会被 `*` 通配符匹配到，放行就会把"我的视频"也放行了。**接口路径设计要为鉴权规则服务。**

### 第 5 步：静态资源映射（让文件能被浏览器访问）

后端代码把文件写进了磁盘，但浏览器访问 `/upload/xxx.mp4` 时，Spring 默认找不到。需要告诉 Spring"这个路径对应磁盘哪个目录"：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Value("${file.upload-dir:./upload}")
    private String uploadDir;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // 用户访问 /upload/** 时，去磁盘 {uploadDir}/ 目录找对应文件
        registry.addResourceHandler("/upload/**")
                .addResourceLocations("file:" + uploadDir + "/");
    }
}
```

> **原理**：`addResourceHandler("/upload/**")` 说"哪些 URL 是静态资源"，`addResourceLocations("file:.../")` 说"这些 URL 到磁盘哪里找文件"。**路径必须以 `/` 结尾，这是最容易写错的细节。**

### 第 6 步：前端（API → 上传页 → 详情页 → 路由）

**① API 封装**（上传是唯一不用 JSON 的请求）：
```js
export function uploadVideo(formData) {
  return request.post('/video/upload', formData, {
    headers: { 'Content-Type': 'multipart/form-data' },
    timeout: 60000  // 大文件上传超过默认 10s，放宽到 60s
  })
}
```

**② 上传页的 FormData 组装**（核心）：
```js
const formData = new FormData()
formData.append('file', videoInput.value.files[0])       // 视频文件
if (coverInput.value.files[0]) formData.append('cover', coverInput.value.files[0])
formData.append('title', title.value.trim())
formData.append('description', description.value.trim())
formData.append('category', category.value)
await uploadVideo(formData)
```

**③ 播放详情页**：后端返回的 `videoUrl` 是 `/upload/20260907/xxx.mp4`，原生 `<video>` 直接播：
```html
<video class="player" :src="video.videoUrl" controls preload="metadata" />
```

**④ 路由**：`/upload`（需登录，`meta: { requiresAuth: true }`）、`/video/detail/:id`（公开）。

## 3. 踩坑记录（这两个坑都是开发时真实遇到的）

### 坑 1：`transferTo()` 保存文件失败，返回"文件保存失败"

- **现象**：上传接口报 `{"code":500,"message":"文件保存失败，请重试"}`。
- **排查**：业务异常不打堆栈（GlobalExceptionHandler 只打未知异常），于是先给上传工具类加上 `log.error` 再看日志。
- **根因**：`MultipartFile.transferTo(File)` 在不同容器下的实现不一致（内部先尝试 rename，失败才复制），在部分环境会直接抛 `IOException`，而且抛出的具体原因难定位。
- **解决**：改用 `Files.copy(file.getInputStream(), target, StandardCopyOption.REPLACE_EXISTING)` —— 显式"读输入流 → 写目标文件"，行为确定，还能顺手加日志。
- **教训**：**上传这类 IO 操作，先确认异常信息能打出来再谈排查**；`transferTo` 与 `Files.copy` 相比，后者更可控、更推荐。

### 坑 2：Vite 代理 `/upload` 拦截了前端路由 `/upload`，投稿页 500

- **现象**：浏览器访问投稿页 `http://localhost:5173/upload` 返回 500"系统繁忙"，但接口都是好的。
- **根因**：为了让 `<video>` 能加载文件，我在 `vite.config.js` 里把 `/upload` 代理到了后端。但**前端路由也叫 `/upload`**！Vite 的代理规则优先于 history 路由回退，于是访问投稿页时请求被代理转发到后端 `http://localhost:8080/upload`，后端没有这个静态资源，抛 `NoResourceFoundException` → 全局异常兜底返回 500。
- **解决**：代理规则改成 `/upload/`（带斜杠）——只代理"文件路径"（`/upload/xxx.mp4`），不拦"页面路由"（`/upload`）。
- **教训**：**代理规则的匹配范围一定要比业务路径窄**。给静态文件配代理时，尽量带上子路径边界，避免和前端路由撞车。

## 5. 进阶方向（模块 1 之后怎么深化）

1. **大文件分片上传 + 秒传**：100MB 限制下，大视频上传体验差。进阶：前端把文件切片并发上传，后端合并；用文件 MD5 做"秒传"。
2. **换对象存储**：把 `UploadUtils` 的存储实现从本地磁盘换成 MinIO（自建）或阿里云 OSS，体验"接口不变、实现替换"的抽象设计。
3. **视频转码**：用户上传的是原始视频，进阶用 FFmpeg 转成多清晰度（720p/1080p），播放器按网速选清晰度。
4. **正式审核后台**：本模块的审核接口是"登录即可调"的测试入口，进阶要做成管理员角色 + 独立后台页面 + 审核记录表。
5. **访问加速**：加 Nginx 直接服务 `/upload/**` 静态文件，让 Spring 只处理业务接口。

## 6. 一句话总结

**本模块的开发路线 = 先定三个设计（存本地、状态机、路径分离）→ 建表 → 上传工具（校验+存盘）→ Service（状态机+权限）→ Controller → 静态映射+放行 → 前端上传/详情页 → 验证。**

**记住三句话：**
> - **文件名和路径永远由后端生成，用户传的一律不信**（白名单 + UUID）
> - **状态是视频的生命周期**：待审核 → 已发布/已驳回，未发布仅作者可见
> - **存储路径和访问路径分离**：磁盘随便放，对外统一 `/upload/**`，换存储不改接口
