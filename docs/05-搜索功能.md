# 05 搜索功能

> 配套项目：my13li13li（Spring Boot 3.2 后端 + Vue3 前端）
> 本文档讲解仿 B 站社区的**搜索**模块：关键词搜视频（分页）、全站热搜词、个人搜索历史，以及前端 NavBar 搜索框下拉与搜索结果页的完整实现。

---

## 模块简介

搜索由两部分组成：

1. **视频模糊搜索**：基于 `video` 表的 `title` 字段做 `LIKE` 查询（只搜已发布的视频），支持"最新 / 最热"排序与分页，接口公开（游客可搜）。
2. **搜索辅助**：热词与搜索历史，全部基于 **Redis ZSet** 实现——`search:hot` 存全站热词（score=搜索次数），`search:history:{userId}` 存个人历史（score=搜索时间戳，天然去重）。每次搜索通过 `POST /api/search/record` 记录一次：热词计数 +1；登录用户同时把关键词写入自己的历史。

前端入口在 **NavBar 顶部搜索框**：聚焦时下拉展示"搜索历史 + 全站热搜 Top10"，回车或点选后带关键词跳转 `/search?kw=xxx`；`Search.vue` 渲染搜索结果卡片网格，支持"加载更多"分页。

注意：**搜索历史存在 Redis（服务端）而不是 localStorage**，这样同一账号换设备历史也能同步，且后端可统一控制条数上限（20 条）与过期时间（30 天）。

## 涉及数据表与 Redis 数据结构

### video 表（搜索目标）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| user_id | BIGINT | 上传用户 ID |
| title | VARCHAR(100) | 视频标题（**LIKE 搜索的目标字段**） |
| description | VARCHAR(500) | 视频简介（当前搜索未使用，仅展示） |
| status | TINYINT | 状态：0待审核 1已发布 2已驳回 3已下架（**搜索只查已发布=1**） |
| play_count / create_time | INT / DATETIME | 播放量 / 创建时间（hot / 最新排序依据） |

> 说明：任务描述中提到的"搜索基于 title/description 等字段"，本项目的实际实现是**只对 `title` 做 LIKE**（`VideoServiceImpl.search` 中 `wrapper.like(Video::getTitle, kw)`），`description` 未参与搜索，仅作展示字段。如后续要搜简介，把 `wrapper.like` 换成 `.and(w -> w.like(title).or().like(description))` 即可。

### Redis 数据结构（SearchServiceImpl）

| Key | 类型 | member / score | 作用 |
|---|---|---|---|
| `search:hot` | ZSet | member=关键词，score=搜索次数 | 全站热词榜，倒序取 TopN |
| `search:history:{userId}` | ZSet | member=关键词，score=搜索时间戳 | 个人搜索历史，倒序=最近在前，member 唯一天然去重 |

两个 key 的 **TTL 均为 30 天**（`KEY_TTL = Duration.ofDays(30)`），**每次写入都刷新过期时间**（滚动过期），防止 key 无限膨胀。

## 后端实现

### 1. 视频模糊搜索（VideoController.search → VideoServiceImpl.search）

`GET /api/video/search` 是搜索入口，SecurityConfig 中已放行（游客可搜）。核心查询：

```java
@Override
public IPage<VideoVO> search(String keyword, long page, long size, String sort) {
    // 关键词：去空格后 LIKE 模糊匹配标题；空关键词等同查全部（返回最新列表）
    String kw = keyword == null ? "" : keyword.trim();
    LambdaQueryWrapper<Video> wrapper = new LambdaQueryWrapper<Video>()
            .eq(Video::getStatus, VideoStatus.PUBLISHED);   // 只搜已发布
    if (StringUtils.hasText(kw)) {
        wrapper.like(Video::getTitle, kw);                  // 标题模糊匹配
    }
    // 排序：hot=按播放量（最热），默认按发布时间（最新）
    if ("hot".equals(sort)) {
        wrapper.orderByDesc(Video::getPlayCount).orderByDesc(Video::getCreateTime);
    } else {
        wrapper.orderByDesc(Video::getCreateTime);
    }
    Page<Video> p = videoMapper.selectPage(new Page<>(page, size), wrapper);
    return p.convert(this::toVO);   // 复用统一的视频 → VO 转换
}
```

要点：

- **只搜已发布**：待审核/驳回/下架的视频不会出现在任何用户的搜索结果里（与公开列表策略一致）；
- **空关键词查全部**：等于返回最新发布列表，前端空搜索也不会报错；
- `toVO` 是项目统一的实体 → VO 转换方法，搜索结果与首页/详情共用同一套字段组装（含封面、作者信息、计数等）。

### 2. 搜索记录（SearchServiceImpl.record）：热词 +1、历史去重写入

`POST /api/search/record` 是**公开**接口（游客也能搜，只记热词不记历史）。每次搜索前端调用一次：

```java
@Override
public void record(String keyword, Long userId) {
    if (!StringUtils.hasText(keyword)) {
        return;   // 空关键词不记录
    }
    // 截断 + 去空格，保证入库的每个词格式统一（去重才生效）
    String kw = keyword.trim();
    if (kw.length() > KEYWORD_MAX_LEN) {
        kw = kw.substring(0, KEYWORD_MAX_LEN);   // 最长 30 字，防止无意义长词污染热词榜
    }
    // 1. 全站热词：搜索次数 +1（ZSet 原子自增）
    stringRedisTemplate.opsForZSet().incrementScore(KEY_HOT, kw, 1);
    // 刷新热词 key 过期时间（滚动 TTL，30 天不活跃自动消失）
    stringRedisTemplate.expire(KEY_HOT, KEY_TTL);

    // 2. 登录用户个人历史：member 用关键词（天然去重），score 用时间戳保证"最近搜索"在前
    if (userId != null) {
        String historyKey = KEY_HISTORY + userId;
        stringRedisTemplate.opsForZSet().add(historyKey, kw, System.currentTimeMillis());
        // 只保留最近 20 条：按 score 从小到大删掉最旧的多余记录（0 ~ -21 是最旧的）
        Set<String> all = stringRedisTemplate.opsForZSet().range(historyKey, 0, -1);
        if (all != null && all.size() > HISTORY_MAX) {
            stringRedisTemplate.opsForZSet().removeRange(historyKey, 0, all.size() - HISTORY_MAX - 1);
        }
        // 刷新个人历史 key 过期时间
        stringRedisTemplate.expire(historyKey, KEY_TTL);
    }
}
```

**热词是"实时维护"而非定时任务**：每次搜索的 `incrementScore` 就是一次计数 +1，无独立的统计/落地流程；TTL 也是写入时刷新（滚动过期），不存在单独的定时清理任务。对练习项目而言，这种方式实现最简单、实时性最好；真实产品通常会在热词榜旁叠加"按天/按小时窗口"的统计（如对 ZSet 按时间片建多个 key 再归并），以体现"今天的热词"而不仅是"累计的热词"。

### 3. 热词与历史查询、清空

```java
@Override
public List<String> hotKeywords(int topN) {
    // score 倒序取前 topN 个关键词（最多返回 N 个）
    Set<String> hot = stringRedisTemplate.opsForZSet().reverseRange(KEY_HOT, 0, topN - 1);
    return hot == null ? List.of() : List.copyOf(hot);
}

@Override
public List<String> myHistory(Long userId) {
    // score 倒序 = 最近搜索在前（最多 20 条）
    Set<String> history = stringRedisTemplate.opsForZSet()
            .reverseRange(KEY_HISTORY + userId, 0, HISTORY_MAX - 1);
    return history == null ? List.of() : List.copyOf(history);
}

@Override
public void clearHistory(Long userId) {
    stringRedisTemplate.delete(KEY_HISTORY + userId);   // 整 key 删除 = 清空
}
```

### NavBar 搜索下拉（frontend/src/components/NavBar.vue）

搜索框常驻导航栏，聚焦时下拉展示"搜索历史 + 全站热搜"。数据来源两个时机：
- 页面挂载时 + 登录状态变化时加载一次；
- **搜索框每次聚焦时重新加载**（热词是实时累加的，挂载时那份数据会过期，聚焦不刷新会导致下拉里永远是旧的热词列表）：

```js
/** 搜索框聚焦：打开下拉并刷新热词/历史 */
function onSearchFocus() {
  loadSearchSuggest()
  searchDropdownOpen.value = true
}
/** 加载搜索建议：全站热搜 + 登录用户的搜索历史 */
async function loadSearchSuggest() {
  try {
    const r = await getHotSearch()
    hotWords.value = r.data || []
  } catch { hotWords.value = [] }
  if (userStore.user) {
    try {
      const r = await getSearchHistory()      // 登录才拉历史
      searchHistory.value = r.data || []
    } catch { searchHistory.value = [] }
  } else {
    searchHistory.value = []                  // 游客没有历史区
  }
}
// 登录状态变化时刷新历史（登录会拉历史，退出清空）
watch(() => userStore.user, loadSearchSuggest)
onMounted(loadSearchSuggest)
```

交互细节：

- 下拉项用 `@mousedown.prevent @click`，避免输入框 `blur` 抢先收起下拉；
- 失焦延迟 200ms 关闭，给下拉项 click 留出时间；
- 点击热词/历史 → `pickWord(w)`：填入关键词并直接触发搜索；
- 清空历史调 `clearSearchHistory()`（服务端删除整个 key）。

```js
/** 搜索：带关键词跳到 /search 出结果；空关键词跳到 /search 出引导页 */
function onSearch() {
  const kw = keyword.value.trim()
  if (kw) {
    router.push(`/search?kw=${encodeURIComponent(kw)}`)
  } else {
    router.push('/search')
  }
  keyword.value = ''
}
```

### 搜索结果页（frontend/src/views/Search.vue）

页面本身**不再自带搜索框**（搜索框在 NavBar），只负责：无关键词时展示引导文案；有 `?kw=` 时搜索并渲染结果网格。

```js
/** 触发一次搜索：记搜索记录 + 拉第一页结果 */
async function doSearch() {
  const kw = keyword.value.trim()
  if (!kw) return
  // 新搜索时显式重置分页状态：避免 page 累加导致第二次搜索请求到第 N 页（命中空集）
  page.value = 1
  videos.value = []
  total.value = 0
  try {
    // 记录搜索（热词+1，登录用户写历史），失败不影响搜索本身
    try { await recordSearch(kw) } catch { /* 忽略 */ }
    await loadPage(true, kw)
    lastKeyword.value = kw
    searched.value = true
  } finally {
    searching.value = false
  }
}

/** 加载一页结果：replace=true 覆盖（新搜索），false 追加（加载更多） */
async function loadPage(replace, kw) {
  const res = await searchVideos({ keyword: kw ?? lastKeyword.value, page: page.value, size: 12 })
  videos.value = replace ? res.data.records : [...videos.value, ...res.data.records]
  total.value = res.data.total
  page.value++
}
```

页面挂载时读取 `route.query.kw`：有值直接 `doSearch()`（从 NavBar 跳转的场景），无值保持引导态（提示"请在顶部搜索框输入关键词，或点击搜索框查看热搜 / 搜索历史"）。

## 关键设计说明

**① 为什么热词和历史都用 ZSet 而不是 List / Hash / 普通 String？**
三者的对比：

- **List**：LRANGE 能按序取，但"关键词去重 + 计数 +1"需要先遍历判断，做不到原子性；
- **Hash**：field 去重方便、计数方便（HINCRBY），但**无法按 score 排序**——热词要"按次数倒序取 Top10"，Hash 做不到；
- **ZSet**：member 唯一（去重）、score 可排序（倒序取 TopN / 倒序取最近历史）、`incrementScore` 原子自增（计数 +1 一次搞定）——三个需求全部原生满足，是"排序 + 去重 + 计数"场景的标准答案。

**② 个人搜索历史为什么去重？重复搜索时 score 被覆盖意味着什么？**
同一关键词再次搜索时，`opsForZSet().add(key, kw, 当前时间戳)` 会用新时间戳**覆盖旧 score**（member 相同即更新），效果是：该词在列表中的位置被"提升"到最前，历史列表永远按"最近一次搜索时间"排序，且不出现重复词条——这正是用户对搜索历史的直觉预期（最近搜过的排前面、同词只出现一次）。

**③ TTL 滚动过期如何防止 Redis key 膨胀？**
`search:hot` 是全局单 key，本身不会膨胀；真正的风险在**个人历史**：每个用户一个 key，若用户量大了且从不清理，key 数量会线性增长。滚动 TTL（每次写入 `expire(key, 30天)`）让"长期不活跃用户"的历史 key 自动过期删除，无需定时任务扫描清理。30 天的窗口对练习项目足够；真实产品会按用户活跃度分层设置。

**④ record 接口为什么公开（游客也能调）？**
搜索是游客可用的能力（视频搜索接口公开），所以"记录搜索"也必须公开，否则游客的搜索行为无法进热词统计。实现上通过 `userId` 是否为空区分：**游客只记热词、不记个人历史**；`myHistory` / `clearHistory` 因涉及个人数据，走默认的登录鉴权。

## 常见问题

**Q1：搜索不到刚上传的视频？**
上传后的视频默认状态是"待审核(0)"，搜索只查 `status = PUBLISHED(1)` 的记录，待审核/驳回/下架都不会出现在结果里。等管理员在审核台通过后即可被搜到。

**Q2：搜索历史的条数上限是多少？超了会怎样？**
每个人最多保留 20 条（`HISTORY_MAX = 20`）。写入时先 `range(0, -1)` 取全量，超过 20 条就用 `removeRange(0, 超出数量-1)` 删掉最旧的那几条（score 最小 = 最久没搜）。清空则是直接 `delete` 整个 key。

**Q3：热词榜为什么可能出现"很久以前的热词"？**
热词是**累计计数**（每次搜索 score +1，滚动 TTL 只防 key 消失、不重置计数），没有按天/按小时的窗口衰减，所以历史搜索量大的词会长期占据榜单。这正是注释里"真实产品按时间片分 key 归并"要解决的问题——练习项目从简，只体现累计热度。

**Q4：清空历史后，热词榜里我的搜索记录还在吗？**
在。`clearHistory` 只删除 `search:history:{userId}` 这一个 key，全站热词 `search:hot` 是全局共享的，不会被个人清空操作影响——这也符合直觉：热搜是社区行为，不是个人数据。
